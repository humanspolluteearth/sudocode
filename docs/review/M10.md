## Converter (PR: feat: Edexcel and Cambridge to Python converter)

Design: `packages/core/src/converter/`. The converter reuses each language's front end (`analyse`) and prints the
shared core IR as Python (an IR printer). `refuse.ts` walks the IR first and refuses anything with no faithful Python
version (files, TYPE/records, TRY, BYREF, devices, dates, classes). `helpers.ts` holds small Python helpers that are
only written into the output when used (`_show`, `_put`, `_copy`, `_right`, `_mid`, `_is_num`, `_range`).

### Things to check by hand

- **Huge non-exact REALs print differently from CPython** (`SH-03-real-large-shortest-form`): the pseudocode prints
  `1e23` as `100000000000000000000000`, CPython's exact value is `100000000000000008388608`-style digits. Left pending
  (`converter/pending.json`). Your call: accept the difference or refuse such programs.
- **Recursion deeper than ~1000** (`SH-13-recursion-1000-calls-deep`): CPython's default limit raises RecursionError.
  The fix is `sys.setrecursionlimit`, but Sudocode's own Python does not support `import sys`, so the round trip cannot
  pass in both. Pending.
- **`EDX-21-empty-array`**: the original program is itself pending in `tests/pending.json` (END FOR vs END FOREACH),
  so the converter correctly refuses it. Pending until the original is fixed.
- **`MISC-refuse-types`**: a `TYPE` declaration that is never used leaves nothing in the IR, so it cannot be
  detected from the IR and converts to a harmless empty program. Pending. The merged test's `types` regex is also
  broader than the feature (matches any `DECLARE x : WORD`); I did not edit it.
- CI `test-core` relies on `python3.12` being on the runner (ubuntu-24.04 ships it). No workflow change was made.
