## Decisions made without you

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                               | Why                                                                                             | Follows             |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ------------------- |
| D1  | INTEGER and REAL input ignore spaces around the number; INTEGER is an optional sign and digits only; REAL also accepts a whole number (`3` is REAL 3)                                                                                                                                                                                                                                                                                  | Python's `int()`/`float()` ignore surrounding spaces; both boards map RECEIVE to `int(input())` | SH-06, PY-01        |
| D2  | BOOLEAN input is TRUE or FALSE in any case (spaces around ignored)                                                                                                                                                                                                                                                                                                                                                                     | Boolean literals are accepted in any case                                                       | EDX-08              |
| D3  | An input error points at the RECEIVE statement (its line and column), wording names the input in quotes and the type in plain words                                                                                                                                                                                                                                                                                                    | The student's line is the RECEIVE; SH-06 asks for a kid-friendly message                        | SH-06, SH-15        |
| D4  | Trace: a FOR pass records the loop variable on the FOR line; output rows hold the printed text without its newline; device output reads `[MOTOR] on`                                                                                                                                                                                                                                                                                   | Matches where the debugger stops and what the console shows                                     | SH-17, EDX-74       |
| D5  | Trace: changing one array element records the array's name with the whole array as the debugger prints it                                                                                                                                                                                                                                                                                                                              | Trace columns are variables (SH-17), and an element is not a variable                           | SH-17               |
| D6  | Starting a run paused: the IDE sends `run` then `pause` at once; the engine stops before line 1 with reason `pause`. No protocol change                                                                                                                                                                                                                                                                                                | The protocol already has `pause`, and the engine starts synchronously                           | protocol.ts         |
| D7  | Step over runs until the next statement in the same or an outer subprogram frame                                                                                                                                                                                                                                                                                                                                                       | Standard debugger meaning; step into/out are M5                                                 | M4 scope            |
| D8  | Run honours breakpoints (Run to breakpoint is the normal Run)                                                                                                                                                                                                                                                                                                                                                                          | Checklist item "Run to breakpoint"                                                              | M4                  |
| D9  | Debugger sessions are `tests/debugger/<ID>-<name>.epc` + `.session.json`, played by `tests/support/session.ts`; their pending IDs are `debugger/<name>`. The harness meta-test "every pending ID is a golden case or another known test" now also counts sessions, the file-protection hook now protects `tests/debugger/`, and `pnpm spec:coverage` counts sessions from their files (with pending state) instead of from test titles | Sessions need commands between pauses, which golden files can't express                         | TEST-PLAN section 5 |
| D10 | Spec IDs go into `scope.json` in the code PR that makes their tests pass (SH-14 in the tests PR, as it passes already)                                                                                                                                                                                                                                                                                                                 | A tests PR can't add in-scope IDs whose only tests are pending without failing `spec-coverage`  | M2 practice         |
