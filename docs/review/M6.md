# M6 review notes: files

Decisions made autonomously (docs/ did not settle them). Please check each one.

1. **Bare file names are lexed with context.** `Scores.txt` is one `file` token only right after READ or WRITE at the
   start of a line (EDX-80). Elsewhere a `.` is still an unexpected character. A name may hold letters, digits,
   `_`, `.` and `-`, and ends at a space.
2. **READ into a new variable makes a STRING** (EDX-82), through the same `define` step as RECEIVE. A variable that
   already has INTEGER, REAL, BOOLEAN or CHARACTER type converts the line to that type.
3. **A bad line from a file** uses `E-RUN-INPUT-TYPE` with a `file` variant that names the file (wording proposed by
   me, in the tests PR #60).
4. **Grid column error** now names the row (`grid[0]`), not `grid[0, 2]` (EDX-24 / EDX-27 wording).
5. **Virtual file system** lives in the driver (`runtime/driver.ts`): names match without case (SH-11); the first
   WRITE of a run replaces the contents (EDX-83); every WRITE sends a `fileWrite` event with the whole new contents,
   batched with output.
6. **Not done:** the M5 "globals assigned from a subprogram" test. Spec Q-EDX-3 is unclear, so I did not guess.
7. **Files panel (UI).** Advanced mode is a new `advanced` preference (default off, per docs/PRODUCT.md), switched with
   a checkbox at the right of the side-panel tabs; the Files tab only exists in Advanced mode. Files are stored as
   one IndexedDB record (`sudocode` / `project` / `files`). Files written by a run are merged into the list as soon as
   `fileWrite` arrives, so a stopped run keeps what it wrote. Import skips names the VFS can't hold.
8. **`pnpm check` is quiet** (`scripts/check.ts`): one line per passing step, full output for a failing step. CI still
   runs lint, typecheck, test and spec:coverage as separate steps, unchanged.
