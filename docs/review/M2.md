## Decisions made without you

| #   | Decision                                                                                                                                                                                                                                                                                                                                       | Why                                                                                | Spec/decision it follows             |

| D1  | While a program has syntax errors, only those are shown; checker errors appear once they are fixed                                                                                                                                                                                                                                             | A line that didn't parse would otherwise cause follow-on checker errors            | SH-15                                |
| D2  | A word is a keyword only where a keyword fits; elsewhere it is a name. So `end`, `step` and `to` can be variable names (`end = middle - 1`, `SET end TO 5`), and a keyword in lower case is still read as that keyword where one is expected                                                                                                   | The exam's own binary search uses `end` as a name (EDX-100, EDX-101)               | EDX-05, EDX-101                      |
| D3  | A name that is never given a value anywhere in the program is a checker error (`E-CHK-UNKNOWN-NAME`, with "did you mean" for a different case). A FOR or FOR EACH loop counts as giving a value, so a loop that never ran gives the runtime "has no value yet" error instead (EDX-56)                                                          | Full pre-run checking of names (DECISIONS); the program can't run correctly anyway | DECISIONS (pre-run checking), EDX-56 |
| D4  | Arithmetic on text (`'Total: ' + 5`), comparing different types (`'5' = 5`), `&` with no text on either side (`1 & 2`), ordering BOOLEANs (`TRUE > FALSE`) and AND/OR/NOT on non-BOOLEANs are checker errors at the operator                                                                                                                   | The operators are defined only for those types; a silent answer would mislead      | edexcel.md 2.4, EDX-13, EDX-26       |
| D5  | `&` writes a REAL or a BOOLEAN exactly as it would print (`'Sum: ' & 0.1 + 0.2` is `Sum: 0.3`)                                                                                                                                                                                                                                                 | One way of turning a value into text                                               | EDX-16, SH-03, SH-04                 |
| D6  | `3.` and `1.2.3` are not numbers (syntax error)                                                                                                                                                                                                                                                                                                | EDX-08 shows `42` and `3.14`                                                       | EDX-08                               |
| D7  | One lowercase-keyword warning per keyword word (`end for` gives two). `ENDIF`, `FOREACH` and `END FOR EACH` give only their own warning, whatever their case, because its fix also fixes the case                                                                                                                                              | One diagnostic per occurrence                                                      | EDX-05, EDX-44, EDX-58               |
| D8  | Error recovery: after a mistake in a line, the rest of that line gives no further error; a block whose first line has a mistake still counts as open; a closer that matches an outer block closes the inner ones too (one error); a closer that matches no open block closes the innermost one (one error); with no block open it is unmatched | Panic-mode recovery that reports each mistake once                                 | M2 checklist (panic-mode recovery)   |
| D9  | Statements from other languages (`OUTPUT`, `PRINT`, `INPUT`, `DECLARE`, `CASE`, `OPENFILE` ...) get edexcel.md 2.11's "is not part of Edexcel pseudocode" with the Edexcel form as the hint, one error per statement; the lines of a `CASE` up to `ENDCASE` belong to it                                                                       | Recognisable constructs never give a confusing syntax error                        | SH-18, edexcel.md 2.11               |
| D10 | An array's type includes its element type: an array of STRING can't replace an array of INTEGER                                                                                                                                                                                                                                                | Arrays hold one type (EDX-25); variables keep theirs (EDX-12)                      | EDX-12, EDX-25                       |
| D11 | `ENDWHILE`, `ENDFOR`, `ENDREPEAT` (one word) are errors with a fix, but still close their block                                                                                                                                                                                                                                                | Only `ENDIF` is a lenient form (EDX-44)                                            | EDX-44, EDX-50, EDX-53               |
| D12 | `length(...)` in another case is `LENGTH`, with the lowercase-keyword warning                                                                                                                                                                                                                                                                  | The built-in's name is part of the command set, like a keyword                     | EDX-05, EDX-90                       |
| D13 | An INTEGER literal beyond the range (`9007199254740992`) is the runtime error "number too large", at the literal                                                                                                                                                                                                                               | SH-07: "exceeding it is a runtime error"                                           | SH-07                                |
