# Cambridge 9618 pseudocode

Source: Cambridge 9618 Pseudocode Guide for Teachers (exams 2027-2029), 2026 syllabus, Langfield & Duddell coursebook. Shared rules in `shared.md` apply too. Pointers (CIE-32) and sets (CIE-33) come after the first CIE release (Q-CIE-2).

CIE pseudocode is now checked against the official Pseudocode Guide for Teachers (for exams in 2027–2029). Most rules are SOURCE; a few things I'd assumed from older guides aren't in this one (several string functions, date functions, `DIV`/`MOD` as functions, `@` for pointers) and were proposed, then decided, or corrected.

Source notes in brackets: (guide) = Pseudocode Guide 2027–2029, (book) = coursebook, (syllabus) = 9618 syllabus 2026.

**Research update:** Cambridge's 2026 guide has the same function list, `WHILE` form, pointer syntax and `CASE` rules as the 2027–2029 guide you uploaded, so the version difference doesn't change the language. The functions missing from the guide are defined in the **insert** printed with every Paper 2 (checked against the June 2025 insert), so they are now SOURCE (insert).

### 3.1 Lexical rules

| ID | Rule | Status |
| --- | --- | --- |
| CIE-01 | Comments start with `//` and run to the end of the line; each line of a multi-line comment starts with `//` | SOURCE (guide) |
| CIE-02 | Keywords in UPPER CASE; lowercase keywords accepted with a warning | SOURCE |
| CIE-03 | Identifiers: letters A–Z, a–z, digits, `_`; start with a letter; no accented letters; keywords can't be identifiers. Identifiers are **not** case-sensitive (`Countdown` and `CountDown` are the same name); mixing casings of one name gives a warning | SOURCE (guide) |
| CIE-04 | Literals: INTEGER `5`, `-3`; REAL with at least one digit each side of the point (`4.7`, `0.0`, `-4.0`); CHAR in single quotes `'x'`; STRING in double quotes `"text"` (empty `""` allowed); BOOLEAN `TRUE`/`FALSE`; DATE `dd/mm/yyyy` | SOURCE (guide) |
| CIE-05 | A REAL written without a leading/trailing digit (`.5`, `5.`) is accepted with a warning | LENIENT (approved) |
| CIE-06 | Assignment arrow `←`. The ASCII form `<-` is accepted silently (students can't easily type ←); the editor may display it as ← | SOURCE |
| CIE-07 | Multi-character strings in single quotes (`'Hello'`) accepted with a warning | LENIENT (approved) |
| CIE-08 | Statements may continue onto the next line where the line is obviously unfinished (the guide wraps long function headers and declarations) | SOURCE (guide) |

### 3.2 Types, declarations and constants

| ID | Rule | Status |
| --- | --- | --- |
| CIE-10 | Types: `INTEGER`, `REAL`, `CHAR`, `STRING`, `BOOLEAN`, `DATE`, `ARRAY`, plus user-defined types (3.4). `FILE` is listed in the syllabus but files are named by strings (3.10) | SOURCE (guide, syllabus) |
| CIE-11 | Using an undeclared variable is a checker error. Some Cambridge guide examples need `DECLARE` lines added before they run | DECIDED (changed 23 Nov 2026) |
| CIE-12 | `CONSTANT <name> = <literal>`; the value must be a literal (not a variable, constant or expression). Assigning to a constant is an error | SOURCE (guide) |
| CIE-13 | An assignment's value must have the variable's type. INTEGER into REAL is allowed (widening); everything else is a checker error (e.g. REAL into INTEGER needs `INT()`) | SOURCE |
| CIE-14 | Using a variable before it has a value is a runtime error ("Total has no value yet") | DECIDED |
| CIE-15 | One `DECLARE` can name several variables of the same type: `DECLARE Temp, Index, Last : INTEGER` (no warning) | DECIDED (23 Nov 2026, Q5) |

### 3.3 Arrays

| ID | Rule | Status |
| --- | --- | --- |
| CIE-20 | `DECLARE Names : ARRAY[1:30] OF STRING`; fixed length; all elements one type; any integer bounds (1 is usual) | SOURCE (guide) |
| CIE-21 | 2D: `DECLARE Board : ARRAY[1:3, 1:3] OF CHAR`; access `Board[2, 3]` | SOURCE (guide) |
| CIE-22 | Index values can be any INTEGER expression (`Names[n + 1]`); outside the bounds is a runtime error naming the bounds | SOURCE |
| CIE-23 | Whole-array assignment `Saved ← Board` is allowed when size and type match | SOURCE (guide) |
| CIE-24 | Group assignment like `Names[1 TO 30] ← ""` is not allowed; error with the hint "use a FOR loop" | SOURCE (guide) |
| CIE-25 | String characters: `MyString[P]` counts from 1 | SOURCE (book) |

### 3.4 User-defined types

| ID | Rule | Status |
| --- | --- | --- |
| CIE-30 | Records: `TYPE <Name>`, field lines `DECLARE <field> : <type>`, `ENDTYPE`; access `Var.Field`; records can be assigned whole (`Pupil2 ← Pupil1`); arrays of records allowed (`Form[i].YearGroup`). Field lines without DECLARE accepted with a warning | SOURCE |
| CIE-31 | Enumerated: `TYPE Season = (Spring, Summer, Autumn, Winter)`; values unquoted and ordered; `+ 1` moves to the next value; comparisons by order | SOURCE |
| CIE-32 | Pointer type: `TYPE TIntPointer = ^INTEGER`; variable `DECLARE P : TIntPointer`. Get a pointer with **prefix** caret `P ← ^Var`; read the value with **postfix** caret `P^`. Implemented safely as references to variables | SOURCE |
| CIE-33 | Set: `TYPE LetterSet = SET OF CHAR` then `DEFINE Vowels ('A','E','I','O','U') : LetterSet`; membership test with `IN` | SOURCE |

### 3.5 Operators and precedence

| ID | Rule | Status |
| --- | --- | --- |
| CIE-40 | Arithmetic `+ - * / DIV MOD`; `/` always gives REAL, even for two integers | SOURCE (guide) |
| CIE-41 | `*` and `/` (and `DIV`, `MOD`) bind tighter than `+` and `-`; otherwise precedence as in Edexcel 2.4 | SOURCE |
| CIE-42 | `DIV` and `MOD` are operators (`7 DIV 2`). The function form `DIV(7, 2)` / `MOD(7, 2)` (used in older guides and the coursebook's `Key MOD(n + 1)`) is accepted with a warning. Floor rules for negatives (SH-10) | SOURCE |
| CIE-43 | Exponent `2 ^ 3` is supported (coursebook form). The guide uses `^` only for pointers, so the two are told apart by type (Q-CIE-1) | DECIDED |
| CIE-44 | Relational `= <> < <= > >=` give BOOLEAN; logical `AND OR NOT` take and give BOOLEAN | SOURCE (guide) |
| CIE-45 | `&` joins STRING and CHAR values. Joining a number is a checker error with the hint "use NUM\_TO\_STR" | SOURCE |

| ID | Comparison and type rule | Status |
| --- | --- | --- |
| CIE-46 | Comparisons need two values of the same type, except REAL with INTEGER and CHAR with STRING | SOURCE (insert) |
| CIE-47 | CHAR and STRING comparisons are case-sensitive (`"Program" = "program"` is FALSE) | SOURCE (insert) |
| CIE-48 | Two records cannot be compared (checker error) | SOURCE (insert) |
| CIE-49 | A one-character string can be used as CHAR or STRING; a CHAR can be assigned to or joined with a STRING; a longer STRING can't be assigned to a CHAR | SOURCE (insert) |

### 3.6 Selection

| ID | Rule | Status |
| --- | --- | --- |
| CIE-50 | `IF <cond> THEN … [ELSE …] ENDIF`; nesting allowed; THEN may be on its own line | SOURCE (guide) |
| CIE-51 | `END IF` (two words) and `ELSE IF` chains accepted with warnings | LENIENT (approved) |
| CIE-52 | `CASE OF <value>` then clauses `<value> :` and ranges `<a> TO <b> :`, then `ENDCASE`. A clause's statements can be on the same line or the following lines. Clauses are tested in order; the first match runs, then CASE ends | SOURCE (guide) |
| CIE-53 | `OTHERWISE :` must be the last clause; `OTHERWISE` without the colon accepted silently (coursebook form) | SOURCE (guide, book) |
| CIE-54 | Comma lists in a clause (`'A', 'E' :`) | SOURCE (book; not in guide) |
| CIE-55 | `CASE OF` followed by an expression (not just a variable) | DECIDED |

### 3.7 Loops

| ID | Rule | Status |
| --- | --- | --- |
| CIE-60 | `FOR i ← a TO b [STEP s] … NEXT [i]`. Loop variable INTEGER; values and step INTEGER expressions; inclusive; `a > b` with positive step runs zero times; negative STEP counts down; stops once past b. The name after NEXT is optional ("good practice") | SOURCE (guide) |
| CIE-61 | Edge cases (STEP 0, changing the loop variable inside, value after the loop) as EDX-54 to EDX-56 | DECIDED |
| CIE-62 | `REPEAT … UNTIL <cond>`: runs at least once | SOURCE (guide) |
| CIE-63 | `WHILE <cond> … ENDWHILE` (no DO). `DO` after the condition accepted with a warning (coursebook form) | SOURCE |
| CIE-64 | Loop and IF conditions must be BOOLEAN | SOURCE (guide) |

### 3.8 Procedures and functions

| ID | Rule | Status |
| --- | --- | --- |
| CIE-70 | `PROCEDURE Name(<params>) … ENDPROCEDURE`; with no parameters `PROCEDURE Name()` | SOURCE (guide) |
| CIE-71 | Calling a procedure without `CALL` is a checker error | DECIDED (changed 23 Nov 2026) |
| CIE-72 | `FUNCTION Name(<params>) RETURNS <type> … ENDFUNCTION`; `RETURN <expr>` ends the function immediately. Functions are used only inside expressions; `CALL` on a function is an error | SOURCE (guide) |
| CIE-73 | Parameters `<name> : <type>`, optionally preceded by `BYVAL` or `BYREF`. Default BYVAL. A mode keyword carries on to the following parameters until another appears (so in `SWAP(BYREF X : INTEGER, Y : INTEGER)` both are BYREF). `BYVALUE` (coursebook) accepted with a warning | SOURCE |
| CIE-74 | Arguments must match the parameters in number, order and type | SOURCE (guide) |
| CIE-75 | BYREF parameters in a FUNCTION: warning ("should not be passed by reference to a function") | SOURCE (guide) |
| CIE-76 | BYREF arguments must be variables, array elements or record fields | DECIDED |
| CIE-77 | Variables declared in a procedure are local; main-program variables are global | SOURCE |
| CIE-78 | Recursion allowed (syllabus 19.2; SH-13) | SOURCE (syllabus) |

### 3.10 Files

| ID | Rule | Status |
| --- | --- | --- |
| CIE-90 | `OPENFILE <file> FOR READ / WRITE / APPEND`; the file is a string literal or a STRING variable | SOURCE (guide) |
| CIE-91 | WRITE creates the file, losing any old data; APPEND adds after existing data; a file is open in one mode at a time | SOURCE (guide) |
| CIE-92 | `READFILE <file>, <var>` reads the next line into a STRING variable; `WRITEFILE <file>, <data>` writes one line; `EOF(<file>)` is TRUE when no lines are left (or the file is empty); `CLOSEFILE <file>` | SOURCE (guide) |
| CIE-93 | Reading a file opened for WRITE (or the reverse), or reading past the end, is a runtime error | DECIDED |
| CIE-94 | Random files: `OPENFILE <file> FOR RANDOM`, `SEEK <file>, <address>`, `GETRECORD <file>, <var>`, `PUTRECORD <file>, <var>` (overwrites the record at that position). The variable is usually a record type | SOURCE (guide) |
| CIE-95 | SEEK addresses count records from the start of the file with the first record at address 1; reading an empty slot is a runtime error | DECIDED |
| CIE-96 | A file still open when the program ends is a runtime error naming the file | DECIDED (changed 23 Nov 2026) |
| CIE-97 | `OPENFILE <file> FOR RANDOM` on a file that doesn't exist is a runtime error (as SH-11 for reading); create it first with `FOR WRITE` | DECIDED (23 Nov 2026, Q9) |

### 3.12 Classes

| ID | Rule | Status |
| --- | --- | --- |
| CIE-110 | `CLASS <Name> … ENDCLASS`; subclass `CLASS <Name> INHERITS <Base>` | SOURCE (guide) |
| CIE-111 | Attributes are declared inside the class as `<name> : <type>`, optionally prefixed PUBLIC or PRIVATE (e.g. `PRIVATE Attempts : INTEGER`); they may be given starting values in the class body | SOURCE (guide) |
| CIE-112 | Methods are PROCEDUREs and FUNCTIONs inside the class, optionally prefixed PUBLIC or PRIVATE. Members are PUBLIC unless stated | SOURCE (guide) |
| CIE-113 | Constructor: procedure named `NEW`. Create objects with `MyCat ← NEW Cat("Kitty", "Shorthaired")`; a subclass constructor calls `SUPER.NEW(…)`; `SUPER.<method>` calls the parent's version | SOURCE (guide) |

| CIE-116 | A subclass method with the same name replaces the parent's (polymorphism, syllabus 20.1) | SOURCE |

### 3.13 Built-in functions

The guide defines seven functions; the insert printed with every Paper 2 defines the rest. Sudocode supports exactly the union below. General rule from the insert: a badly formed call, or an argument or operand of the wrong type or value, is an error.

| ID | Function | Returns | Status |
| --- | --- | --- | --- |
| CIE-120 | `LEFT(S, x)`, `RIGHT(S, x)`, `MID(S, x, y)` (x counts from 1), `LENGTH(S)` | STRING / INTEGER | SOURCE (guide, insert) |
| CIE-121 | `LCASE(c)`, `UCASE(c)`: non-letters returned unchanged | CHAR | SOURCE (guide) |
| CIE-122 | `TO_UPPER(x)`, `TO_LOWER(x)`: x is CHAR or STRING, result has the same type; digits and spaces unchanged | CHAR or STRING | SOURCE (insert) |
| CIE-123 | `NUM_TO_STR(x)`: x INTEGER or REAL; negatives start with '-' (`NUM_TO_STR(87.5)` gives "87.5") | STRING | SOURCE (insert) |
| CIE-124 | `STR_TO_NUM(s)`: s CHAR or STRING; a leading '-' gives a negative | INTEGER or REAL | SOURCE (insert) |
| CIE-125 | `IS_NUM(s)`: TRUE if s (CHAR or STRING) is a valid number, e.g. "-12.36" | BOOLEAN | SOURCE (insert) |
| CIE-126 | `ASC(c)`, `CHR(n)` (ASCII values) | INTEGER / CHAR | SOURCE (insert) |
| CIE-127 | `INT(x)`: integer part, truncating toward zero for negatives | INTEGER | SOURCE |
| CIE-128 | `RAND(x)`: random REAL from 0 up to but not including x | REAL | SOURCE (guide, insert) |
| CIE-129 | Dates: `DAY(d)`, `MONTH(d)`, `YEAR(d)`, `DAYINDEX(d)` (Sunday = 1), `SETDATE(day, month, year)`, `TODAY()` (current date; not NOW) | INTEGER / DATE | SOURCE (insert) |
| CIE-130 | `EOF(file)`: TRUE when no lines are left; an error if the file isn't open for READ | BOOLEAN | SOURCE (guide, insert) |

### 3.14 Out of scope

Assembly language, declarative (Prolog-style) programming and SQL are exam theory in the syllabus, not part of Sudocode's CIE language.
